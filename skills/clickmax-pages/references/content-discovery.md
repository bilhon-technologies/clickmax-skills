# Content discovery before page authoring

Run for a new page or funnel before writing its HTML. Read the request and available account context first; reuse supplied answers across every page.

## Decide what still needs an answer

- Default = guided discovery for missing content. “Use the platform default design”, “no visual reference”, or “execute with MCP” selects neither automatic mode nor permission to invent facts.
- Explicit “automatic”, “infer everything”, or “skip discovery” → skip optional questions, choose reversible creative decisions, and record factual gaps in the draft. A skipped answer is not a supplied fact.
- Already requested creation → answers complete the brief and authorize continuing the requested draft; do not add an assembly confirmation. Blueprint-only request → return the blueprint.
- Ask only missing, material facts. Never re-ask price, offer, dates, capacity, guarantee, deliverables, or design already supplied. Resolve existing products/offers through their skills; never ask for hidden ids.

## Ask in the client's conversation

Use structured input if the client supports it; otherwise ask the same questions as concise numbered text and wait for the response. No special Clickmax questionnaire tool is required. Never silently bypass discovery because the client has no form UI.

Ask at most 3 questions per round, grouping related content:

1. **Proof:** can the user provide real testimonials/authorized quotes and results, explicitly request clearly labeled fictional examples for a draft, or omit proof for now?
2. **People and visuals:** who teaches or represents the offer, and which approved bio, portrait, brand assets, screenshots or certificate artwork are available? Allow omission or illustrative visuals; never infer a real identity, qualification, endorsement or accreditation.
3. **Delivery:** request the actual WhatsApp group invite, access URL or other promised next-step destination when missing. If the user does not have it, record it as pending and keep the delivery action non-interactive in the draft; never invent a working link or use `#` as if it grants access.

Offer omission/delegation per optional question and an explicit skip-discovery choice. Additional rounds are only for remaining material ambiguities. A certificate explicitly promised by the user is an included deliverable; missing artwork does not require reconfirming that promise or justify claiming external accreditation.

### Example: live Excel bootcamp

Request already specifies 3 pages, selected R$47 offer, 20 seats, October 15–17, 19:00–22:00, recordings, templates, completion certificate, WhatsApp support and 7-day guarantee, with default design.

Ask only: “Você tem depoimentos reais para usar, prefere exemplos fictícios identificados apenas no rascunho ou quer deixar essa seção de fora?”; “Quem ministra e quais fotos, materiais ou modelo do certificado você pode enviar? Podemos deixar esses blocos pendentes.”; “Qual é o link real do grupo do WhatsApp? Se ainda não tiver, deixarei o acesso pendente no rascunho.”

Use supplied event facts; do not add an unprovided year/timezone. Adapt the default design without another visual questionnaire.

## Record the brief and continue

Track `supplied facts | user-selected omissions | explicitly requested fictional samples | creative assumptions | pending delivery/assets`. Reuse it across the funnel; ask again only when new ambiguity changes the result.

- Real proof → preserve meaning and attribution; use only authorized assets.
- Fictional samples → only after explicit request/selection; visibly label the section **“Exemplos fictícios — somente rascunho”** and each quote **“Exemplo fictício”** (translate to page language). Use neutral sample labels, no real names/photos, and no invented measurable results or implied actual customer experience. Replace/remove all fictional samples before publication; a hidden comment or final-chat warning is insufficient.
- Unanswered proof → omit, or use an explicitly labeled empty draft preview with literal field labels, never plausible fabricated evidence.
- Missing delivery URL → keep a visible pending notice and no live-looking access button; report the missing URL before publishing. Continue independent authorized draft work.
- Inference may shape benefits, objections, FAQ, composition and positioning from supplied context. It must not manufacture customer evidence, scarcity, dates, guarantees, certifications or performance claims.

Before publication, inspect rendered pages for fictional/empty proof and pending access destinations. Resolve or remove them; report remaining gaps rather than claiming a ready-to-publish funnel.
